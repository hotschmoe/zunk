# Source notes

## build.zig

Bridge dependencies are emitted in the listed order. The user's `bridge.js` is
emitted last so it can override dependency symbols. Fonts are copied into
`dist/fonts/` and loaded before the app's `init` runs.

Build configuration never starts a process. `-Dcommit=<id>` supplies the tester's
provenance string and defaults to `unknown`, including in fetched dependencies.
CI passes its checkout SHA. `tools/test.mjs` reads the checkout SHA and passes it
to the fixed-seed fuzz invocation in the blocking gate.
That invocation inherits the outer build's optimization mode.

## tools/tidy.zig

`zig build tidy` measures source with Zig 0.17.1's `std.zig.Ast`. The blocking
`test` step runs tidy before starting `tools/test.mjs`; compilation can run in
parallel. Tidy is a build lint, not another end-to-end test. `-- --table` prints
Markdown rows, source totals and repository totals. The longest-function total
is a maximum; other totals sum groups, including their separate deficits.
Wall time uses the awake clock and includes discovery, git and ratchet checking.

The program is copied between zunk and teak. All repository policy lives in the
typed `config` block at its top: source roots, skipped directory names, group
rules, generated-file markers, script exclusions and additional banned helper
names. A compiled block keeps this policy small, checked by Zig and colocated
with the program; a separately parsed configuration file would add another
input and failure path. The ratchet remains runtime data so tightening does not
recompile the tool. There is no shared package or repository-name detection.

Zunk's style scope is `src/**/*.zig`, `tools/**/*.zig`, `examples/*/src/**/*.zig`,
`build.zig` and `examples/*/build.zig`. Root patterns ending in `/` include
descendants; other patterns match exactly. One `*` matches an example directory.
Groups are each direct directory under `src`, `src/*.zig`, `tools`, `examples`,
and the root build file. Group rules match prefixes in order; `directory`
selects the next directory component when present, otherwise the rule's name.
Discovery skips `.git`, `.zig-cache`, `zig-out`, `zig-pkg`, `.archive`,
`node_modules` and `ref`, and does not follow symlinks. A file with `GENERATED`
or `Generated by` in its first eight lines is excluded and named in every report.

`held_files` in `tools/tidy_ratchet.zon` is a hand-maintained list of source
paths. Each file has its own group, excluded from its directory's counts, and
must meet every style target independently of its stored numbers. It must
exist, be in scope and not be skipped or generated. Duplicate and noncanonical
paths fail. Updates preserve the entire list, including when a file is missing;
they never remove entries. Zunk holds `src/assert.zig`, `src/fuzz.zig`,
`src/fuzz_generate.zig`, `src/gen/build_path.zig`, `src/gen/wasm_reader.zig`,
`src/gen/wasm_analyze.zig`, `src/gen/js_identifier.zig`, `tools/tidy.zig` and
the simulator (`src/sim.zig`, `src/gen/serve_sim*.zig`).
Seam inventories and globals may be nonzero; style targets are zero, with
longest function at most 70. Moving a held file
out of a group also moves its assertion demand and surplus credit.

The columns mean:

- `files`, `lines`, `functions`: included files, physical lines (a final newline
  adds no empty line), and function declarations with bodies. Bodiless
  prototypes and function pointer types are excluded. `type_functions` is the
  subset with explicit return expression `type`; it remains in `functions`.
- `long_lines`: lines exceeding 100 Unicode code points, including comments
  and ordinary quoted literals. Tabs count as one column; display widths are
  not modeled. A line whose AST token is `multiline_string_literal_line` goes
  into `literal_long_lines` instead. This reports embedded JavaScript, shaders
  and other multiline data without ratcheting them as Zig style violations.
- `long_functions`, `longest_function`: physical span from `fn` through the
  closing body token, inclusive of signatures, comments and blank lines. Type
  constructors are exempt from both metrics; their methods count.
- `assertions`: calls whose final identifier is `assert`, regardless of receiver.
  Ownership belongs to the innermost function, including nested methods.
  `trivial_functions` counts bodies with exactly one top-level AST statement,
  including a lone return or the owned assert's conditional panic. Such functions
  contribute neither assertion demand nor credit. Other functions require two
  assertions on average within their group: `assertion_deficit` is
  `max(0, 2 * nontrivial_functions - assertions_in_nontrivial_functions)`.
  Extra assertions in one nontrivial function can cover another's deficit.
  `functions_no_assert` still reports all bodies with no assertion calls.
  Sites sample under-asserted nontrivial functions, rather than numeric deficits.
- `usize_fields`, `sized_fields`: struct fields typed `usize` or `?usize`, versus
  explicit `uN`/`iN` or their optional form. Tuple fields count. Union members,
  enum tags, aliases, pointers, arrays and slices do not. `isize` is not `usize`.
- `self_recursion`: functions calling themselves. `mutual_recursion`: unordered
  function pairs with calls in both directions, once per pair. Bounded stacks
  assign container scopes and function ownership; measurements scan the flat
  AST. Bare names resolve through enclosing containers to file scope. Field
  calls resolve through a uniquely named local container, `self`, `Self`, or
  the caller's first parameter. Ambiguous names, imports, aliases, function
  pointers, arbitrary receiver types, indirect calls and cycles longer than two
  are not resolved. The first-parameter heuristic can mistake a function-pointer
  field for a method. Comptime and syntactically bounded recursion still count.
- `while_true`: while nodes with literal `true` conditions. This neither proves
  other loops bounded nor inspects exits within these loops.
- `camel_case`: lowercase-initial function names with an uppercase ASCII letter,
  excluding type constructors. Escaped identifiers are not normalized.
- `allocation`, `clock`, `environment`, `threads`, `files_io`, `processes`: potential banned
  calls, once per category per call. One call can count in several categories.
  These expose seams; they do not prove an allocation happens after startup.
- `globals`: container-member `var` declarations at file scope or in any struct,
  union or enum, including containers declared inside functions (static locals).
  `threadlocal` and extern variables count; `const`, instance fields and ordinary
  call-local variables do not. Membership comes from the AST, independent of
  function ownership. Each declaration counts once, even inside generic types.
  This inventory exposes persistent state for the simulator's repeated runs;
  it does not distinguish a cache from a registry or prove semantic determinism.
- `scripts`: git-tracked `.sh`, `.py`, `.mjs`, `.js` and `.ps1` files, excluding
  `src/gen/js/` (shipped application code) and `ref/` (read-only prior art).
  Shipped JS is not tooling; counting it as tooling would measure the wrong debt.
  Untracked Zig files are measured too. `tests` counts AST test declarations in
  every discovered nongenerated Zig file, even outside style scope. Held files' tests belong to
  their individual group; all other tests and all scripts belong to `repository`,
  so totals do not double-count. The stored test count is a ratchet like the
  others: zero here, and in a repository that still has tests it can only fall.
- `clock` includes `std.Io.Timestamp.now`; `threads` includes `io.concurrent` and
  `io.async` task spawns, by method name.

The standard allocation field-call names are `alloc`, `alignedAlloc`,
`allocSentinel`, `allocWithOptions`, `allocAdvanced`, `create`, `realloc`, `remap`,
`dupe`, `dupeZ`, `dupeSentinel`, `allocPrint`, `allocPrintSentinel`, `append`,
`appendSlice`, `appendNTimes`, `appendFlattened`, `ensureTotalCapacity`,
`ensureTotalCapacityPrecise`, `ensureUnusedCapacity`, `addOne`, `addManyAsSlice`,
`resize`, `put`, `getOrPut`, `fetchPut`, `putNoClobber`, `initCapacity`,
`toOwnedSlice`, `toOwnedSliceSentinel`, `readFileAlloc`, `readFileAllocOptions`,
`utf16LeToUtf8Alloc` and `createMap`. `join` and `concat` also match through
`std.fs` or `std.mem`. Bounded forms such as `appendAssumeCapacity`,
`putAssumeCapacity` and `bufPrint` are excluded. Receiver types are not inferred:
GPU `resize` and our bounded `Buffer.append` can be false positives; aliases and
wrappers with different names can be missed. Native resource creation allocates too.

Clock calls contain `std.time` or `Io.Clock`, or use the clock/timestamp names
in `clock_names`: libc and kernel clock queries, `sleep`, `nanosleep`, `usleep`,
Windows timing and Mach time. `std.Io.sleep` counts as clock access. Environment
names cover libc `getenv` and setters, standard environment helpers and Windows
get/set APIs, plus `init.environ_map` and `minimal.environ` chains. Thread calls
contain `std.Thread` or `Io.Threaded`, use `pthread_`/`thrd_` APIs, clone or thread
helpers; raw futex operations count too. Clone counts as both thread and process
access because flags determine what it creates.

File calls contain `std.fs` except `std.fs.path`, `Io.Dir`, `Io.File`, or use the
standard file names in `file_names`. Path helpers operate on strings and do not
count as IO; allocating `join` still counts as allocation. `stdio_names` adds
libc stdio, including `fopen`/`fopen64`, `fread`, `fwrite`, `fclose`, seeking,
stdio output, temporary files and pipe streams, plus `dlopen`/`dlclose`/`dlsym`.
`std.DynLib` calls count as file access. `raw_file_names` covers descriptor IO,
metadata, directories, links, mappings, sync and file watches through `std.c`,
`std.posix` and `std.os.linux`. Common names such as `read`, `close` and `remove`
require a raw receiver, so an application collection's `remove` is not file IO.
Raw reads/closes of sockets also count: descriptor kind is not inferred.

`processes` covers `std.process.spawn`, `run`, `replace`, libc/kernel exec,
fork, spawn, wait, process identity and signals, and Windows process launch APIs.
It counts call sites, not the number of children. `popen`/`pclose` count as both
file and process access. Ambiguous `wait`/`kill` require a raw receiver or bare
call; child instance `wait`/`kill` are not inferred, while their spawn is counted.

Token chains ignore whitespace and comments. One file-level `const` alias to a
field-access namespace is recognized for raw APIs, `std.Thread`, `std.DynLib`
and `std.process`. This is lexical inventory: it does not resolve local shadows,
alias chains, arbitrary receivers, imports, syscall numbers, function pointers,
native extern calls with other names or differently named application wrappers.
Name-only matching can overcount same-named application methods. The arrays in
the program are the complete name lists, reviewed against Zig 0.17.1's standard
sources; they also cover common libc externs a program can declare itself.

Zunk currently adds no allocation, environment or file helper names. Tidy
necessarily uses allocation, a clock, files and git; held files allow and ratchet
these seam inventories and globals.

Every discovered `build.zig.zon` must have the same decoded
`minimum_zig_version`, including tool manifests. Missing values, invalid syntax
and disagreements fail independently of ratchets. This checks manifest agreement,
not CI's installer or agreement between separately reported repositories.

`-- --table --root <path>` opens another tree read-only, measures all discovered
Zig files (including root-level files), and groups them by first directory or
`*.zig`. It never reads or writes a ratchet or applies zunk's held list. The
same directory and generated exclusions apply. Scripts use filesystem discovery
there, including untracked files, because fetched packages need not have git
metadata. Tests are reported without enforcing zero. `--root` and `--update`
cannot be combined. Use this for rich_zig and the fetched webzocket package;
their source and manifests are never modified.

The ratchet is parsed with `std.zon`. Its metric-name header fixes numeric row
order. Stored metrics are long lines/functions, longest function, deficit,
usize fields, recursion, literal infinite loops, camelCase, banned-call counts,
globals, scripts and tests. Sizes, assertions, trivial functions and literal long
lines are reported only. Every stored number must match exactly. Decreases fail until
`-- --update` records them; increases are refused even by update. A raise is
legitimate in three cases: a count that was always there has become
visible (tidy learned to see it, or an implicit operation was made explicit); a
call moved from one group into another, lowering the first by at least as much;
or a long function in old code was split, adding a function to the assertion
average. The stored number is then edited by hand and the change report explains
why.
Held-file regrouping can likewise remove surplus assertion credit from a group;
this accounting change needs an explained hand edit. New metrics are seeded by
hand. Replacing tidy itself re-seeds only its seam inventories; its style stays
at target. The complete snapshot is validated before writing. A new group must
start with zero long lines/functions, deficit, usize fields, recursion,
while-true, camelCase and tests,
and longest function at most 70. Seam counts may be nonzero. Existing debt is
seeded once by hand; update cannot bootstrap it. Removed groups measure zero
until update drops them. Failures name group, metric, before/after and at most
twenty current file:line samples. Vanished sites have no remaining location.

One startup allocation reserves `State`; it is released at shutdown. Limits:
2 MiB per input, 4,096 files/directories/held paths, 65,536 entries per directory,
2,048 functions and 4,096 containers per file, 524,288 tokens/nodes, nesting
depth 256, 128 groups, 512 bytes per path, 20 sites per metric/group, 256 KiB
report buffer and 64 MiB parser scratch. Git output is capped at 2 MiB and
4,096 names. Limits return named errors and fail; nothing is silently omitted.
No owned heap memory is acquired after startup. The standard AST/ZON parser
requests temporary allocations from the reserved scratch, reused between inputs.
This compiler-workspace exception permits the required standard parser API
without arena growth. Standard IO and process internals are outside that owned
workspace guarantee. Traversal uses a bounded queue; syntax ownership uses
bounded stacks. The standard parser may recurse; tidy's functions do not.

## src/gen/build_path.zig

`build` is the pure in-memory seam from wasm bytes and generation options to
analysis, JavaScript, HTML, source map, report, hash and import dispositions.
It receives all storage and limits from its caller and does no IO, clock reads
or random draws. A fixed-buffer allocator uses the caller's one allocation;
there is no allocator growth. The CLI still owns its IO and uses the same
reader and generator directly.

The reader caps input at 10 MiB and each vector at 65,536 entries. The seam
defaults to 1,024 imports, 65,536 option bytes and a 268,435,456-step budget.
Options allow at most 128 fonts and 64 bridge chunks; option bytes include
filenames, URL, integrity, font names/files, and bridge origins/bodies. These
limits return `InputLimit`, `EntryLimit`, `ImportLimit` or `OptionLimit`.
Insufficient caller storage returns `OutOfMemory` or the writer's `WriteFailed`.
No limit failure publishes a partial result.

Every reader byte and payload slice is charged against the shared step budget.
Before generation the seam reserves `(wasm_bytes + option_bytes) * 128 +
imports * 262144` steps, including bounded 64-by-64 suggestion comparisons.
An insufficient budget returns `StepLimit`. Publication starts empty with stage
`reader`; after analysis and reservation it changes to `generation`. Only full
success publishes a result. Failure leaves scratch storage unspecified and the
result null; the stage identifies which phase exhausted storage.

## src/gen/wasm_reader.zig and src/gen/wasm_analyze.zig

The reader extracts function types, imports, exports, the local-name subsection
of `name`, and the opaque bytes of `zunk_bindings`. Other custom payloads and
unrecognized name subsections are skipped. Custom section names still use the
same checked UTF-8 name reader. Manifest bytes are retained, not JSON-validated.

Every other section is skipped by its declared size: function, table, memory,
global, start, element, code, data, data-count, tag (13), and future section IDs.
Their bytes are never interpreted. The browser validates those payloads and
their relationships. Zunk is a build tool, not a wasm validator; rejecting a
new instruction, segment encoding or section would break otherwise usable apps.
Only type/import/export uniqueness and type-before-import order are enforced.
Import signatures must refer to available types. Names attach to imports already
read when the custom section is encountered; other custom placement is allowed.

Bounds checks cover every read, slice and vector count; unsigned LEB128 takes
at most five bytes and cannot overflow u32. Names must be UTF-8. Vectors must
fit the remaining payload as well as the entry limit. SIMD `v128` is a known
value type, including in signatures used only by internal functions. Unknown
value types return `UnsupportedValueType`. Imported table/memory limit flags
0 through 3 are read without comparing minimum and maximum; higher flags return
`UnsupportedLimits` because this reader has u32 limits. All malformed framing,
unsupported input and resource exhaustion return typed errors. Analysis returns
no partial value on error. Owned assertions cover programmer invariants and
remain enabled in all optimize modes.

## src/fuzz.zig and src/fuzz_generate.zig

This executable exercises the real reader, resolver and JS/HTML generator through
the build-path seam. Startup allocates three 16 MiB regions plus two 64 KiB
case buffers; generation and oracles reuse them. The runner owns IO, random seed
selection, timing and the active-case pointer used by the panic saver. The pure
generator receives its seeded PRNG explicitly. Cases allow at most 128 imports;
the run defaults to 4,096 iterations and caps explicit runs at 10,000,000.

Sixteen profiles cross twenty mutation choices. Profiles include empty and many
imports, duplicate module/name pairs, exact/prefix/signature resolution, unknown
symbols, long/empty/Unicode/quoted names, other namespaces, all four import kinds,
an internal v128 parameter, shared imported memory, tag and future section IDs.
The three expectation classes and their oracles are:

- `accept`: a well-formed reader input must build. Two different scratch regions
  must produce identical JS, HTML, report, source map, hash and dispositions.
- `reject`: damaged headers, section framing, type/import/export fields, custom
  section names or name-subsection framing must return the same typed reader
  error twice and publish nothing. Resource failures cannot stand in for input
  rejection. Truncations cover thirteen section positions. Bindings content is
  opaque; its custom-name/framing damage is rejected, not arbitrary manifest bytes.
- `skipped`: change a payload byte in one of eleven skipped section kinds while
  preserving all framing. The damaged module must build twice deterministically;
  every generated output must also equal the undamaged baseline byte for byte.
  Both builds receive identical options derived from their unchanged length.

For accepted cases, the independent declaration list must match every analyzed
and reported import in order, including duplicates. The oracle resolves each
declaration against its analyzed signature. An import is `provided` exactly when
it is a function from `env` and the resolver finds a binding other than a stub.
The emitted disposition must agree, and the report must classify every remaining
import as `stub` (an emitted env function fallback) or `missing` (no generated
entry). This checks accounting, not the behavioral correctness of each JS binding;
it deliberately shares the production resolver. Custom bridge code is opaque
and cannot be credited as providing an import by static inspection.

Accepted cases also probe one-byte storage, 4 KiB storage, one step, zero allowed
imports, and zero option bytes. Each required limit returns its typed error with
no result; the 4 KiB probe counts generation-stage exhaustion when reached.

Counters record accepted/rejected reader cases, generation-stage storage failures,
provided/unresolved imports, duplicate pairs, zero/many imports, custom names,
deterministic pairs, no-output rejections, memory/step/import/option limits,
source-map/font cases, well-formed/skipped/identical-baseline classes, and the
v128/shared-memory/tag/future-section cases. Arrays count every profile, mutation
and truncation position. Runs of at least 512 cases require every scalar and array
counter to be nonzero. Replay runs check just the saved case and skip coverage.

The first line prints `fuzz seed=<seed> iterations=<count> commit=<id>`; the final
line reports elapsed seconds and cases per second. Omit `--seed` for an IO-supplied
random seed. Pass `-Dcommit=$(git rev-parse HEAD)` to identify the code being run;
the default is `unknown`, and a dirty working tree is not encoded in the SHA.
Failure prints the seed, case number, commit, reason and replay path, and saves
`zig-out/fuzz/seed-<seed>-case-<number>.wasm` with a `.wasm.expect` sidecar.
Skipped cases also save `.wasm.baseline`; keep all siblings together. Replay with
`zig build fuzz -- --seed <seed> --replay zig-out/fuzz/seed-<seed>-case-<number>.wasm`.
Replay uses the saved expectation and baseline, reconstructing declarations only
for accepted input, so a broken reader can still replay malformed cases.

## src/bind/bind.zig

The exchange buffer is shared with JavaScript and reused for successive strings;
callers must copy data they need to retain. Callback ID zero denotes failure or
no callback, and registered IDs are not reused.

## src/web/ime.zig

The hidden textarea holds focus during text input. Set it active while a text
field is focused, update its spot with the caret's canvas-relative CSS position
and line height, and poll once per frame. Printable keys use the input typed-text
path. The update cursor is a byte offset; an empty commit after a composition
means cancellation. Event text aliases the poll scratch buffer. Records that do
not fit in scratch stay queued; records read into scratch beyond the output
array's capacity are discarded.

## src/web/input.zig

Pointer and viewport coordinates and wheel deltas are CSS pixels; wheel deltas
are positive down and right, and line or page modes are converted to pixels.
Trackpad pinch arrives with Ctrl set. The canvas backing dimensions scale CSS
dimensions by device pixel ratio. Modifiers reflect the most recent event;
typed text consists of whole UTF-8 code points, excluding control characters and
Ctrl/Cmd chords. The meta modifier is Cmd on macOS and the Windows key elsewhere.

## src/web/audio.zig

Audio decoding is asynchronous. Loading audio from bytes returns a handle before
decoding completes; poll `isReady()` before playing it.

## src/web/asset.zig

Asset fetch is asynchronous; poll `isReady()` before using the result.

## src/web/app.zig

Wasm entry points that call `std.log` must set `std_options.logFn` to
`zunk.web.logFn`: the default pulls in `std.Io.Threaded`, unavailable on
wasm32-freestanding. Browser log messages longer than 512 bytes are truncated.

## src/web/fx.zig

The host-services protocol is described in `docs/ARCHITECTURE.md` and
`src/gen/js/fx.js`. JavaScript copies request data before returning and queues
results until `poll`; it calls into wasm only during that poll. Caller-chosen
request IDs should be nonzero; unsolicited completions use zero. Completion
slices remain valid only until the next poll, which frees the previous batch.
JavaScript must refresh its memory view after allocating a record, since wasm
memory may grow. Delivery transfers ownership to the inbox.

Completion fields depend on kind: HTTP uses `a` for status (zero for transport
failure) and blobs for body and error; file-opened uses name, MIME, and bytes;
downloaded, storage-value, and query-value use `a` as a success or found flag;
clock uses `a` for UTC offset in minutes and an eight-byte little-endian Unix
millisecond value in its first blob. Dropped uses `a` for file/image/text,
`b` and `c` for image dimensions, `d` for thumbnail width, and blobs for name,
MIME, bytes, and thumbnail RGBA. Pasted-text uses its first blob for text.

The file picker waits for a user activation if none is active. Image clipboard
writing requires a secure context and user activation. An empty storage value
deletes the key. `encodeHeaders` skips empty or colon-containing names and
fields containing line breaks; its caller frees the returned buffer.

## src/gen/source_map.zig

Source maps cover bridge chunks at line granularity and embed their source;
generated lines outside these spans remain unmapped. Span ends are exclusive
and cannot precede their starts. Callers skip map generation when there are no
spans. A trailing partial line counts as a line.

## src/gen/dev_server.zig

Startup claims the loop and real IO adapter once from the caller's allocator,
using `rawAlloc` to avoid the Debug allocator API's undefined-byte poisoning.
Control fields are initialized in place; payload arrays are neither assigned
from aggregate literals nor cleared. `rawFree` releases the reservations after
shutdown without poisoning them. The four snapshots reserve 200 MiB plus
script space, but only bytes actually read for responses become resident.
Keeping four independent sparse reservations preserves four simultaneous
validated responses; a small streaming buffer cannot validate the complete
file before sending its first body byte. A single snapshot would reduce
address space at the cost of that concurrency, without improving idle RSS.
Connection buffers, socket task buffers and traversal storage also have fixed
startup capacity. The caller owns configuration slices for the server lifetime.

Server-owned state never allocates after startup. The portable std IO backend
can allocate task records and worker threads for `io.concurrent`, and std
process spawning constructs temporary argv/environment and platform resources.
Those allocations belong to std, not growable server containers. Shutdown
cancels and joins socket tasks, terminates/reaps the child tree, joins file IO,
then releases storage. The prior server is archived in `.archive/serve.zig`.

## src/gen/serve_io.zig

`Interface` is the only outside-world boundary of `Loop`: listen, accept,
nonblocking read/write, close, proxy connect/status, file snapshot submission,
watch submission, build submission/cancellation, wait and diagnostic sink.
Socket handles are opaque u32 values (adapter slot indices in real IO); no OS
types cross this interface.
Transfers return pending, a positive short count, closed, or failed. File,
watch, listen, connect and submission errors have the `Failure` error set.
Build completion carries success/cancellation, bounded output, truncation and
IO failure. The terminal sink cannot affect the state machine's decisions;
a failed sink returns `System` and shuts down the server.

The interface combines socket readiness with completions for blocking work.
The real adapter implements readiness with tasks: an empty transfer slot is
ready to accept an operation; a working slot is not ready; a completed slot
is ready to return its result. Reads and writes return pending while their
task works on adapter-owned bytes. Closing cancels and joins those tasks
before recycling the slot. No socket task borrows a connection's live storage.
`wait` receives bounded interests, whether admission is enabled, and an absolute
deadline in monotonic milliseconds. It returns one ready token, admission,
file/watch/build completion, timer, or stop, stamped with monotonic time. It
may return a timer early; it must wait rather than repeatedly return empty
events without advancing time. Each readiness token describes the interests
from that particular wait; it is not retained after a slot is reused.

File submissions are open/stat, positional read, verify/stat-and-close, or
close. Results carry size/inode/mtime/ctime, a possibly short read count, both
verification metadata records, or closure. An open failure retains no handle;
verification closes even on error. Each index owns at most one open file and
one outstanding operation. Each read borrows a slice of the fixed snapshot
buffer until exactly one completion with its index. The adapter must not
access that slice after delivering completion. The loop compares metadata,
decides which read follows, probes EOF, and decides whether to serve or reject.
Watch and build each permit one outstanding submission; builds remain
outstanding until termination/reaping and completion delivery, including after
cancellation. Close is synchronous and invalidates the handle. No cancellation
can release a borrowed file buffer early. These ownership rules let a simulator
delay and reorder completions without accessing live server state.

The simulator (src/sim.zig and src/gen/serve_sim*.zig) implements this table
directly: readiness, short transfers, reset/EOF, short file reads and
independently changed metadata, watch observations, child output and result,
timer advancement and stop. It chooses event order and virtual times from its
seed. OS metadata, fingerprint collisions, kernel behavior and webzocket
internals remain outside the simulation boundary.

## src/gen/serve_loop.zig

One thread owns all connections, snapshot ownership, timers, revisions, build
state and browser notification state. It holds no locks and calls no OS API.
Every turn handles at most one completion/readiness event, then bounded timer
and notification work, then waits. Socket writes are at most 64 KiB per turn.

| Connection state | Event | Next state / action |
|---|---|---|
| free | accept | request; reserve slot and request deadline |
| request | short read | accumulate until complete headers |
| request | complete GET | file, handshake, proxy_connect, or error header |
| file | open/stat completion | reject oversize, or begin bounded positional reads |
| file | read completion | advance cursor; at expected end probe one extra byte |
| file | EOF probe | verify metadata and close handle |
| file | stable verification completion | header; retain immutable snapshot |
| file | changed/read error/limit | error header; release snapshot |
| header | header fully written | body |
| body | partial write | body; advance cursor |
| body | body fully written | free; close and release snapshot |
| handshake | fully written | websocket |
| websocket | received frame | package decode; ping gets pong; close frees slot |
| websocket | status/reload due | queue one frame; track target generation |
| websocket | frame fully written | advance delivered status/build generation |
| proxy_connect | upstream writable | check connection; proxy_request or 502 |
| proxy_request | request fully written | proxy_read |
| proxy_read | upstream bytes | proxy_write |
| proxy_write | client chunk fully written | proxy_read |
| any live state | reset/EOF/deadline | free; close handles; forget client |

An in-flight snapshot whose client disappears becomes ownerless until its
completion arrives; it cannot write into storage reused by another request.
The client slot itself is immediately reusable. Proxy upstream interests are
disabled while buffered bytes are being sent to the client, so upstream EOF
cannot discard those buffered bytes.

| Rebuild state | Event | Next state / action |
|---|---|---|
| idle | source observation | increment change revision; debounce 100 ms |
| idle | debounce deadline | running; record revision and submit one child |
| running | source observation | pending; remember latest revision |
| pending | further source observation | pending; coalesce into the same follow-up |
| running/pending | 120 s deadline | terminate child tree; await completion |
| pending | child completion | idle; start follow-up after completion |
| running | failed/crashed/cancelled child | idle; publish error status |
| running | successful child | idle; request a fresh watcher observation |
| idle, publication pending | fresh observation without a newer source change | publish build |
| idle, publication pending | newer source observation | withhold publication; rebuild again |

An outstanding watch at child completion is consumed, by its result or by its
error, but cannot authorize publication; another watch is requested. Dist changes accumulated during a
build plus the fresh observation decide whether HMR is wasm-only. Every
successful final build publishes even if its output metadata did not change.
External dist changes while idle also publish. Failed build output is not
announced as reloadable. A subsequent success clears the browser overlay.

`change_revision`, `started_change` and `completed_change` order observed
source changes and builds. `published_build` orders browser notifications.
Each client keeps `notified_build` and an in-flight `sending_build`; only a
fully written frame advances notification state. A later publication while a
frame is partly written remains due afterward. Status/error delivery has its
own revision, so an error or clear cannot overwrite an in-flight reload.
Joining clients start at the publication current when accepted and receive
any later publication, including one completed during their handshake.

Local assertions check that file cursors reach the initial size before
verification, no build starts while one is running, completed
source revisions match publication, notified generations cannot exceed the
published generation, transfers fit their buffers, and snapshots cannot be
reused while IO owns them. The remaining properties are temporal:

- A response is an immutable, validated snapshot, never a stream from a file
  changing length while read. A failed validation sends 503 with no file bytes.
- After the last *observed* source change, eventual successful rebuild and fair
  writable IO deliver a reload/HMR to every still-connected reload client for
  a build started after that observation. Persistent failures instead deliver
  error status; no implementation can promise a successful reload if every
  build fails or never exits. Polling cannot see changes between observations
  that restore identical metadata. Delivery means the socket accepted every
  frame byte, not an application acknowledgement from the browser.
- A disconnect clears the entire connection record. Snapshot IO ownership is
  retired separately; it cannot prevent reuse of the connection slot.
- Each turn advances a bounded cursor/state, submits work, or waits on IO.
  Deadlines bound slow clients and hung builds; there is no retry spin.

| Limit | Result |
|---|---|
| 16 ordinary connections | 17th uses refusal slot, sends 503 and closes |
| one refusal in progress | disable accept until sent/closed; kernel backlog provides backpressure |
| accept failure | visible diagnostic; disable admission for 500 ms before retrying |
| 4 simultaneous snapshots | 503 and visible counted diagnostic |
| 50 MiB file | larger file gets 413 and visible counted diagnostic |
| 4,096 request bytes | incomplete headers get 431; requests accumulate short reads |
| 1,024 target/path bytes | 414; watched paths get PathLimit; startup config is rejected |
| one pending source change | coalesce further observations; latest revision retained and logged |
| one child | new observations become pending; no concurrent rebuild |
| 60,000 combined child output bytes | retain prefix, drain remainder, count and report truncation |
| 60,512 output bytes/client | occupied pong slot closes with counted diagnostic |
| 256 incoming bytes; 125 payload | unmasked, fragmented, extended frames close with diagnostic |
| 30 s request deadline / transfer inactivity | close and report; idle WebSockets have no timeout |
| 120 s rebuild | kill child tree, reap, deliver error; then process pending change |
| u64 revision/event lifetime | bounded loop / typed `System` at revision or clock exhaustion |

The connection limit includes reload clients. The injected script is bounded
at 1,536 bytes. HTTP headers reserve 512 bytes;
their formats and MIME vocabulary have bounded lengths. The extra script
space is reserved in every snapshot. Refusal and error responses retain the
same isolation and no-cache headers as successful files.
Clock events above `maxInt(u64) - build_timeout_ms` return `System` before
deadline arithmetic can overflow. Diagnostic text has a 60,064-byte limit and
a fixed 60,065-byte sink buffer including its newline.

## src/gen/serve_http.zig

HTTP accepts bodyless GETs and closes after one response. Short reads accumulate;
query strings are excluded from file lookup. Traversal and backslash paths are
forbidden. Missing extensionless paths fall back to index.html; favicon has an
embedded fallback. HTML receives the reload script; other file bytes are exact.
The proxy forwards the original complete GET headers and streams its response
through bounded connection storage. It does not parse or rewrite the backend's
response. Only plain HTTP proxy targets are supported.

Webzocket remains unchanged. `Handshake.createReply` performs the response
handshake, `proto.writeFrameHeader` encodes outgoing frames, and
`proto.Reader.read/done/deinit` decodes input from a caller-owned static buffer.
The package owns neither a socket nor a thread here. A provider with maximum
zero and failing allocator disables fallback allocation; compressed, fragmented
and extended-length incoming frames are rejected before package decoding.
Input is read one frame at a time, including a separately accumulated two-byte
prefix, so following frames cannot bypass the input policy. This is sufficient
for the reload client, which sends no application messages, and supports ping.
There are no required webzocket changes for this use. General fragmented or
large-message support would need a bounded package reader/provider contract;
it is not a second parser implemented in zunk. Rich_zig remains the CLI console
package; the loop's diagnostic sink uses bounded raw text through IO.

## src/gen/serve_files.zig

The file adapter opens and stats regular files, performs one positional read
per job, and returns handle/path metadata while closing at verification. The
loop tolerates short reads, probes one byte beyond the expected end, then
compares the metadata. Size, inode, mtime and ctime must agree; replacement,
growth, shrinkage and observed same-size rewrites return `Changed`. A writer
that pauses with an apparently stable incomplete file cannot be identified
without its cooperation. Requests during an owned rebuild get 503. Atomic
publication by other writers is outside the server's control.

The adapter polls on requests from the loop, normally 500 ms after the previous
watch completion. Sources are all regular files recursively under configured
watch paths (default src), plus configured watch files (build.zig and
build.zig.zon). Dist watches regular files directly in the served root, as
before. No symlink traversal occurs during recursive discovery. Order-independent
fingerprints include path, inode, size, mtime and ctime, separated into wasm and
other output. The lexicographically first wasm name makes HMR selection stable.

Traversal uses a 1,024-directory queue and a 65,536-entry budget per source/dist
scan, plus at most 65,536 explicit watch files. Exhaustion reports `WatchLimit`;
paths exceeding 1,024 bytes report `PathLimit`; failed scans report their typed
error and retry after the polling interval. The prior successful fingerprint
remains the comparison point for a failed individual scan. Fingerprints are
observations, not a filesystem transaction or a collision-free change journal.

## src/gen/serve_os.zig

One adapter serves Linux, macOS and Windows using blocking `std.Io` networking,
files, directories, clocks, mutexes and conditions. Blocking operations run in
`io.concurrent` tasks. One persistent task serializes file jobs and watcher
scans; one accept task, at most one connect task per upstream, and at most one
read and one write task per socket post completions to adapter storage. Rebuilds
use a supervisor task with separate pipe-drain and child-wait tasks. The std
Threaded backend supplies the threads and may retain idle workers for reuse.
The number of live operations is bounded by the slots, not by request count.
Workers never access `Loop`, connection records or rebuild/notification state.
A mutex and condition protect only the adapter mailbox and its IO buffers.

There are 34 socket slots, each with independent 64 KiB input/output buffers,
four file job/result slots with persistent handles, one watch slot and one
child slot. Each file job reads at most 64 KiB before yielding a completion.
The loop owns the borrowed file slice until completion; shutdown joins file IO
before releasing it. An occupied submission slot returns `Busy`. Bounded
cursors select completions and readiness fairly. The mailbox lock covers both
predicate checks and condition waiting, preventing lost wakeups. Waits end at
the next loop deadline or within 50 ms to observe shutdown signals; spurious
wakeups recheck predicates rather than returning empty events in a busy loop.
`Future.cancel` requests cancellation at std IO cancellation points and joins
the task. Close waits for this before closing a stream or reusing its buffers.

## src/gen/serve_process.zig and src/gen/serve_child.zig

Startup validates at most 32 arguments totaling 8,192 bytes; empty executable
names and embedded NULs return `InvalidConfig`. `std.process.spawn` supplies
portable executable lookup, inherited environment, null stdin and output pipes.
The prior adapter's separate environment and PATH-candidate limits no longer
apply because std owns that transient storage.

The supervisor detaches stdout/stderr from `Child` so its waiter cannot close
pipes while drain tasks still use them. Two tasks drain 4 KiB chunks even
after the combined 60,000-byte retained prefix fills. A capture mutex protects
that IO result only. A separate waiter owns `Child.wait` and signals an event.
Canceling the supervisor interrupts its event wait; it terminates the child
tree, awaits the uncanceled waiter to reap, then cancels/joins drain tasks.
Normal exit also terminates remaining descendants before draining to EOF.
This avoids canceling POSIX `Child.wait`, which cleans up its child record even
when interrupted. Each drain has a u32-maximum read-count bound; exhaustion
marks IO failure. Combined output order is the observed capture-lock order.

All OS selection is in `serve_process.zig`, at comptime. Linux and macOS use
std process spawn with `pgid = 0`, POSIX group KILL and saved/restored INT/TERM
sigactions. Windows uses suspended std spawn, a Job Object with kill-on-close,
assignment before ResumeThread, and TerminateJobObject. Windows console Ctrl-C
and Ctrl-Break use SetConsoleCtrlHandler. These handlers only store a lock-free
atomic stop flag; the loop sees a stop event within 50 ms. The handler owner
is single-instance process state, guarded by lifecycle assertions. There are
no Linux-specific syscalls, OS-specific socket adapters or fallback servers.

## src/sim.zig and src/gen/serve_sim*.zig

The dev-server simulator is the second implementation of `serve_io.Interface`
and the checkers that judge the real `serve_loop` run against it. `src/sim.zig`
is the runner and the only file of the set that touches the clock, files,
arguments or allocation; it reserves the loop and the simulator once with
`page_allocator` (the loop's snapshots are 200 MiB of sparse address space) and
runs the real loop in the same process. The other files are pure: no clock,
file, thread, environment or global state, static storage only.

- `serve_sim.zig`: the thirteen interface calls, the world scheduler and
  `wait`. Every call validates its contract (handle open, one outstanding job
  per index, one watch, one build, `connected` only after completion, buffer
  bounds) and records a trace entry.
- `serve_sim_client.zig`, `serve_sim_plan.zig`: the clients. A client is a
  request byte stream (whole or in pieces, with gaps), a reading speed (prompt,
  slow, stalled), a disconnect plan (half close, FIN or RST at a time or after
  N received bytes) and, for WebSocket clients, a plan of masked frames. The
  seventeen request kinds cover files, fallback, favicon, missing, path and
  header edges, 414/431/413, traversal, bad requests, stalled and dribbled
  requests, proxy, reload clients and bad handshakes.
- `serve_sim_rx.zig`, `serve_sim_ws.zig`: response parsing. Bytes are checked
  as the server writes them: status line and reason, the six fixed headers,
  content length, and for a file the 16-byte stamp at the start of the body
  names (file, inode, version, size) so every later byte can be checked against
  the content function without storing the body.
- `serve_sim_files.zig`, `serve_sim_jobs.zig`: the file tree, whose files are
  rewritten, replaced, deleted and created, and the file, watch and build jobs
  with their delays, errors and short reads. Content is a pure function of
  (file, inode, version, offset). A transaction is clean when open, every read
  and verify saw one version; a 200 must carry the bytes of a clean transaction.
- `serve_sim_proxy.zig`: the proxy target (accepts, refuses, stalls; response
  length, reset, hang).
- `serve_sim_oracle.zig`: build, debounce, publication and snapshot-occupancy
  state computed only from the events the simulator delivered, not from the loop.

The simulator draws everything from one `Xoshiro256` seeded by the seed and
advances only virtual time. `wait` runs the world at the current time, collects
what is deliverable (accept, readiness per interest, completions), delivers one
chosen by the generator, and otherwise advances time to the earliest of the
world's next action and the loop's deadline. It never passes the deadline, and it
sometimes returns a timer early. Reads and writes return partial counts (1, a
few, hundreds, all), pending, closed or failed; readiness is sometimes spurious
and `closed` is sometimes set for a peer that went away.

Checkers, each derived from what the simulator delivered or observed:

- every accepted handle is closed once, never used after close, and none remains
  at exit; an open connection missing from the interests is a violation; a
  connection that must close in this dispatch (response complete, peer EOF or
  reset, write failure, unsupported or close frame, pong with output pending)
  and is still open at the next `wait` is a violation;
- the 17th connection is refused exactly when 16 are open;
- responses are well formed and complete; 4xx and 5xx statuses and bodies must be
  justified by simulator facts (a build outstanding, four snapshots possibly
  held, a file mutated since accept, an injected error); 414, 431, 413, 403 and
  400 are exact;
- the idle deadline: an unexplained close happens at exactly the last reset plus
  30,000 ms, where the resets the loop can make are visible (accept, a write that
  moved bytes, the first write interest of a response, a WebSocket frame
  becoming pending); a connection still open at that time is a violation; idle
  WebSockets have no deadline and closing one without pending output is a
  violation; an unanswered valid request is a violation unless a file job was
  stalled past 30 s;
- `cancel_build` is called exactly 120,000 ms after `build`; `build` is called
  exactly 100 ms after the last observed source change, or at the completion that
  followed a change seen during the build; none without a change;
- publications are computed from build completions, watch observations and their
  submission order (stale and fresh watch, withheld when a newer change is
  observed, none for failed or cancelled builds). A reload client receives, for
  publications after its join, one reload each when it reads promptly; publications
  between accept and join coalesce into one; slow readers get at least one and at
  most the count; no client receives more than the publications since its accept;
  the last status frame (clear or error) matches the last build;
- pings are answered in order with their payload, unless output was pending;
- snapshots held (outstanding IO plus connections serving a 200) never exceed
  four, and a snapshot-limit response needs four possibly held at some moment
  since accept (a snapshot stays held until its connection closes);
- proxy: the request reaches the target byte for byte, the response is the
  target's bytes, a refused or failed connect is a 502;
- liveness: after the world goes quiet (no new clients, edits or frames; slow
  readers speed up) the loop reaches no pending work within 4,096 steps;
- determinism: the runner runs every fourth seed twice and compares the trace
  hash; `tools/test.mjs` compares the campaign hash of two processes.

A second run per seed injects one hard failure into a call (listen, file, watch,
build, wait, log, or a clock past the overflow bound) with an error chosen from
the eight `Failure` values by `seed % 56`; the loop must return exactly that
error and close everything. Soft errors (accept, read, write, connect, file
results, watch results, build results) occur in the main runs.

Coverage counters (request kinds, errors, limits, timeouts, failure variants)
are printed and enforced when a campaign has at least 8 seeds: a zero counter
fails it. The blocking gate runs seeds 1 to 32 of 700 steps with ReleaseSafe
(about a third of a second); the loop copies its 60 KB `Event` several times
per turn, which dominates the cost of a step. A failing run prints its seed, saves
`zig-out/sim/seed-<seed>-<fault>.trace` (header with seed, steps, fault and
hash, then the last 16,384 interface events) and `--replay <file>` reruns from
the header and compares the hash. A panic in the loop saves the trace too.
`zig build sim -- --seed N --steps M [--seeds K] [--replay file] [--budget S]`;
`sim-heavy` runs 120 s of fresh seeds and is part of `test-heavy`.

Not modelled: HTTP pipelining and bodies, HEAD and other methods beyond the 400
path, IPv6, metadata equality after a restored rewrite, kernel buffering, the
adapter's task machinery, and webzocket internals beyond its reader. Turned
down: running the loop against real sockets under the simulator (not
deterministic), a checker that reads the loop's own state (it would agree with
the loop by construction), and injecting a hard failure at a random call of a
long run (one in two seeds would end early; the paired fault run keeps the
main runs long).

## Dev server build and end-to-end gates

`zig build check-size` installs the host CLI and fails above 64 MiB. The Linux
Debug binary is about 20 MiB; the budget is loose because size differs by OS and
optimize mode, and what it guards against is fixed-capacity state being emitted
into the binary (one draft of the dev server was 776 MB). It is a lint in the
blocking gate, alongside tidy. The blocking end-to-end list is CLI build,
version, help, example build, deploy, 512-case generation, a fixed-seed
dev-server simulation (run in two processes, which must print equal campaign
hashes) and dev server.
The dev-server check fetches page/JS/wasm and compares them with disk (HTML
after removing its injected reload script), opens Node's built-in WebSocket,
opens a raw second WebSocket, sends a text frame and two pings and expects both
pongs on the still open connection (the reader runs from a static buffer with the
provider maximum at 0, which a webzocket change once nearly broke),
changes the example source, waits for successful rebuild/reload, restores the
source in finally, awaits server exit and checks PID disappearance/port release.
Initial watcher completion (`watch: ready`), socket events and bounded requests
synchronize it; no startup/debounce sleeps stand in for completion. Node kills
processes directly on Windows, so this check cannot exercise console Ctrl-C
there. Job kill-on-close still handles an interrupted rebuild.

`zig build check-cross` compiles and links without installing or running six
CLIs: x86_64/aarch64 Linux, Windows GNU and macOS. Each instantiates webzocket
and rich_zig for its own target. `test-heavy` depends on this step in addition
to its browser examples. Build configuration does not launch processes.
The simulator replaces the OS adapter, so it does not exercise macOS or Windows
runtime IO/cancellation; cross compilation does not verify those either. Their
blocking CI runs exercise those paths.

## src/main.zig

Bridge dependencies are loaded in CLI order, followed by the first project
bridge found (`bridge.js`, then `js/bridge.js`) so the project can override
dependency symbols. A missing requested font stops the build to avoid silent
fallback. Deploy filenames hash JavaScript before the source-map trailer, but
SRI covers the final served bytes. The build fingerprint includes the zunk
executable as well as the project's inputs, so rebuilding the generator
invalidates its cache.

JSON reports use one streaming stdout writer for the report and newline. Creating
another positional writer just for the newline can overwrite the first report
byte when stdout is redirected to a regular file.

## src/gen/js_resolve.zig

Exact bindings take precedence over the double-underscore internal fallback.
The file-dialog bridge returns paths via the shared string buffer; open/save
mode is 0/1 and patterns are semicolon-separated Win32 globs. File System
Access pickers must start in the originating user gesture. The accessibility
bridge's record and string buffers are valid only for the duration of each
call; its wire format is in `src/gen/js/a11y.js`.

Text cluster rasterization writes coverage bytes, or straight-alpha RGBA for
the color variant, and reports width, height, bearings, and advance. A zero
byte count means no ink or insufficient output capacity; metrics remain valid.

## src/gen/js_gen.zig

Generated bridge chunks are emitted in order, with user code last. Source-map
spans cover chunk bodies only and are measured before the generated header is
rewritten. WASM bindings are mutable so HMR retargets closures to the current
instance. Input flushing is driven by wasm to avoid clearing state early.

Only function imports in `env` are emitted. Unknown env functions get warning
stubs; tables, memories, globals and other modules get `missing` report entries,
without stub bodies or name suggestions. JSON entries include the import kind;
`stubs` counts actual fallback functions and `missing_imports` counts absent
entries. Instantiation receives `{ env }` and takes memory from `exports.memory`;
it does not construct an imported memory. Supplying a missing import requires
extending the import object before instantiation, including from bridge code.
There is no additional per-import terminal warning outside the requested report.

Valid identifiers keep plain method syntax. Reserved words and other names use
computed JSON-string keys so arbitrary UTF-8 names cannot break JS syntax.
The double-underscore fallback has an empty body: an inline line comment would
consume the generated method's closing brace.

Fonts load before startup by default; `--font-nowait` still preloads them but
does not wait. HMR state preservation requires both serialization and hydration
exports and uses the shared exchange buffer; otherwise the new module starts
fresh. HMR failure triggers a reload. WebGPU initialization starts early to
overlap wasm download; a failure offers `window.zunkFallback` before showing
the unavailable message.

Input modifiers are latched until flush, so quick chords retain their modifier
state. Ctrl/Cmd+V is delayed until its paste event or an 80 ms timeout, keeping
paste data and the key in the same frame. Browser shortcuts and real form
fields remain available. Focus loss clears held input, and pointer move and
release listeners live on the window to handle drags outside the canvas.

## src/gen/js_identifier.zig

Identifier classification follows ECMAScript's ID_Start/ID_Continue properties,
plus `$`, `_`, and continuation-only ZWNJ/ZWJ, and excludes reserved words.
The owned Unicode 17.0 tables were extracted from Node's Unicode properties;
no process, external data or runtime dependency is needed to classify names.
Each sorted range stores its gap from the preceding range and its inclusive
length as unsigned LEB128. Base64 keeps the checked-in data compact. Decoding
and range validation happen at compile time. Runtime lookup uses at most eleven
binary-search steps per property and scans at most the name's byte length.

## src/gen/js/ime.js

The hidden textarea handles IME and virtual-keyboard text. The normal input
layer already consumes printable keydowns; paste and drop use host services, so
the textarea ignores those input events. Its record format is little-endian:
32-bit kind, UTF-8 byte cursor, and byte length followed by text padded to four
bytes. Kinds 1, 2, and 3 mean composition start, update, and commit; only an
update carries a cursor. The queue holds at most 64 records and drops the oldest
on overflow. Its selection is read during poll, after the browser updates it.

## src/gen/js/fx.js

Completion records have a 40-byte little-endian header: kind and ID, four
signed integer fields, then four blob lengths. Unpadded blobs follow in order.
The field meanings and ownership rules are in the `src/web/fx.zig` section.
Picker requests wait for user activation when needed; a new request cancels the
armed or open one. Image ingestion downscales to `MAX_IMAGE_SIDE` and creates
an RGBA thumbnail; an unscaled JPEG retains its original bytes, otherwise the
image is encoded as PNG.

## src/gen/js/a11y.js

The accessibility DOM is derived from Teak's semantic tree, never an authority;
actions are returned to Teak through its normal input path. The little-endian
wire format is also described in Teak's `src/platform/wasm.zig`. Published
64-byte records contain command index, role, label offset and length, bounds,
state, flags, value offset and length, selection byte offsets, parent record
index (0xffffffff for a root), and level. Parents precede children. Returned
16-byte actions contain kind, command index, string offset and string length;
kinds 0 through 4 mean activate, focus, set value, increment, and decrement.
Oversized values that do not fit the action string buffer are dropped.

## src/web/gpu.zig

GPU handles index the JavaScript table: zero means none and one is the device.
Passes and command buffers are consumed when ended, finished, or submitted.
The frame encoder and canvas view are created lazily and released by `present`;
do not retain them across frames. Render passes, including offscreen passes,
use the frame encoder, so later passes can sample earlier output. Compute can
share it or use a separate encoder and submission.

`bufferDestroy` and `destroyTexture` kill the handle at once. While the frame
encoder is open the GPU object lives until `present` has submitted the frame,
so a resource recorded in it may be destroyed before `present`. A separately
created encoder gets no such deferral: destroy after its `queueSubmit`.

Texture creation from assets and buffer mapping are asynchronous. Mapping moves
from idle to pending to mapped, or failed until unmapped. Submit the copy with
`present` or `queueSubmit` before requesting the map. `Readback` manages this
sequence. The raw descriptor layouts and enum ordering must match the JavaScript
readers; bind group layout `type_variant` is interpreted according to its entry
type as a buffer binding, texture sample, or sampler binding type.

Stencil attachments require the stencil aspect and a matching stencil-capable
format; pipeline stencil defaults to a no-op and the reference is per draw.
Attachment sample counts must match the pipeline. Null color selects the canvas
format or view as appropriate, and null depth forbids a depth attachment.

Canvas-sized depth and multisample targets must match the canvas pixel size;
MSAA targets resolving into the canvas also use its format. Multisampled
textures are render attachments only and must resolve to a single-sample texture
before sampling or reading. `writeTextureRegion` needs COPY_DST usage and a
source of at least `bytes_per_row * (height - 1) + width * bytes_per_pixel`
bytes; its source stride need not be 256-byte aligned. Texture-to-buffer copy
rows do require 256-byte alignment.

Text cluster metrics position bitmap pixel (0,0) at `(pen_x + bearing_x,
baseline_y - bearing_y)`. Coverage results use one byte per pixel and RGBA
results use four; a truncated result retains valid metrics for retry. Readback
requires encode, submit, request, then polling across frames before reading.
Its rows have the padded stride and region readback indices are region-relative.
